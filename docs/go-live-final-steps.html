ASupabase Auth 配置（约 5 分钟）

目标：让注册能发验证邮件、验证链接能跳回你的网站。

A1 · 打开 Supabase 控制台

浏览器打开 https://supabase.com/dashboard，点进你的项目（项目地址是 https://bwkpcljqjgzrmvnthnkf.supabase.co）。

A2 · 开启邮箱确认（Confirm email）

  1. 左侧菜单点 Authentication（认证）
  2. 顶部切到 Sign In / Providers 标签
  3. 找到 Email 区块，把 Confirm email 开关 打开
  4. （可选）把 Allow anonymous sign-ins 保持 关闭

A3 · 配置回调地址（最关键）

  1. 在 Authentication 下，点左侧 URL Configuration
  2. Site URL 填：https://rootline.vercel.app（先按这个填，部署后如域名不同再回来改）
  3. Redirect URLs 点 Add URL，加入下面两条：
    http://localhost:3000/auth/callback（本地调试用）
    https://rootline.vercel.app/auth/callback（生产用）
  4. 点 Save
💡 顺序提示：域名（rootline.vercel.app）要等部署后才知道最终值。可以先按上面填，等 Step B 部署完拿到真实域名后，再回来核对一次即可。

B部署到 Vercel（约 10 分钟）

目标：把 GitHub 上的代码跑成一个公网网站。

B1 · 导入项目

  1. 打开 https://vercel.com，用你的 GitHub 账号登录（就是 blackLei1986）
  2. 点 Add New… → Project
  3. 在仓库列表里找到并点 Import 你的 rootline 仓库
  4. 框架会自动识别为 Next.js，构建命令、输出目录都用默认值，不用改

B2 · 填环境变量（8 个，照着填）

在 Environment Variables 区逐个添加。带 敏感 的值从你本地 .env.local 文件里复制。

变量名填什么值怎么拿
NEXT_PUBLIC_SUPABASE_URLhttps://bwkpcljqjgzrmvnthnkf.supabase.co直接复制这一栏
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY公开 从 .env.local 复制打开本地 .env.local，复制对应值
SUPABASE_SERVICE_ROLE_KEY敏感 从 .env.local 复制同上，仅服务端，绝不外传
NEXT_PUBLIC_SITE_URLhttps://rootline.vercel.app先填这个，部署后如域名不同再改
CRON_SECRET自定 随机长字符串终端跑 openssl rand -hex 32 生成
FEED_FETCH_CONTACT你的邮箱随便填个真实邮箱
CLOUD_LEARNING_ENABLEDfalse本轮先关，验证通过后再开
RSS_READING_ENABLEDfalse同上
⚠️ SUPABASE_SERVICE_ROLE_KEY 是最高权限密钥，只能填在 Vercel 的环境变量里，绝不能写进代码或公开文档。

B3 · 部署

  1. 点 Deploy，等 1–3 分钟构建完成
  2. 构建成功后 Vercel 会显示一个网址，形如 https://rootline.vercel.app（也可能带随机后缀，如 rootline-abc123.vercel.app）
  3. 记下这个真实域名，下一步要用

C部署后收尾（把真实域名填回去）

拿到真实域名后，回来核对两处，确保验证邮件链接指向正确地址。
  1. Vercel → 你的项目 → Settings → Environment Variables：如果 NEXT_PUBLIC_SITE_URL 填的和真实域名不一致，改成真实域名，重新 Deploy 一次
  2. Supabase → Authentication → URL Configuration：把 Site URL 和 Redirect URLs 里的 rootline.vercel.app 替换成真实域名（保留 localhost 那条）
