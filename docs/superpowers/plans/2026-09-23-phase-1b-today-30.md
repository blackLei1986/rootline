# Rootline Phase 1B Today 30 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a persistent, resumable, frozen Today learning session with 30 ordered targets, three blocks of ten, Root-first/Support fallback selection, target-level learning activities, mastery/SRS integration, and a completion lock.

**Architecture:** Keep the existing Today API, plan snapshot, Supabase ownership model, and learning/SRS engine. Expand the frozen snapshot with target snapshots and add transactional target/session progress persistence with idempotent events; reuse current word progress helpers for learning outcomes. Replace the required Today sequence and dashboard entry while leaving Reading as an independent feature.

**Tech Stack:** Next.js App Router (read the installed version's guides before code changes), TypeScript, React, Vitest, Playwright, Supabase/Postgres migrations and pgTAP.

**Spec:** `docs/superpowers/specs/2026-09-23-phase-1b-today-30-design.md` (derived from the user brief at `/Users/leipan/.codex/attachments/89bb9435-f466-4cfb-a7e3-e42638ec6e93/已粘贴的文本.txt`)

## Global Constraints

- Daily target capacity is exactly 30 when the catalog can supply 30 distinct eligible targets; never duplicate a target to fill capacity.
- Prioritize yesterday's unfinished targets, essential weak targets, reliable Root Core, then high-value Support Words.
- Support Words may not receive invented root or morphology assignments.
- Prefer approximately 24–30 reliable Root Core targets when available; disclose actual composition rather than fabricate morphology.
- Aim for at least approximately 20 Root Core targets in normal current-data conditions; carryover and genuinely essential weak words take priority when they consume capacity.
- Limit non-carryover weak/reinforcement allocation to five targets so due SRS does not swallow the finite Today commitment.
- Carry unfinished targets forward from the immediately preceding user-local learning date only; a partially completed carried target remains in that day's plan and can carry forward again, capped at 30 total.
- Split the target order into 3 blocks of 10; persist block and target progress across refresh and device sessions.
- Freeze one plan per user and local learning date; no user-facing regeneration after plan creation/start.
- Today does not require Reading 2.0 or article reading; keep Reading independently accessible.
- Preserve user-owned data, Supabase RLS boundaries, idempotent writes, and the existing mastery/SRS semantics.
- Validate desktop, 390px, 430px, and 768px layouts; test timezone/date rollover and interrupted sessions.

## Review Focus

- Fewer than 30 distinct eligible words: keep the actual count, never duplicate or fabricate — planner/service tests.
- More than 30 carryover/weak candidates: enforce the finite cap and deterministic priority — planner tests.
- Morphology metadata missing or uncertain: downgrade to Support or omit, never infer — candidate eligibility tests.
- Duplicate/replayed interaction after retry or refresh: apply progress and SRS once — event repository tests.
- Local midnight/timezone rollover: preserve the user's learning-date plan and only create the next local-date plan after rollover — API/service tests.
